# 新增回测策略「重点板块-进攻延迟 n 分钟」（n = 15/20/25/30）

## Context

用户要求在回测系统新增一组策略：在「快进快出」策略的基础上，把买点向后延迟 n 分钟，并要求这 n 分钟内「主力资金净流入的 5min 桶一直为正」且「大盘成交量 5min 桶一直在增加」才买入；卖点完全沿用快进快出；选股改为在延迟窗口内「进攻」tag 板块中涨幅上涨最多的板块，取它与全量自选股的交集，再在交集内选最近 3 日涨幅最大者（涨停顺延、抗分歧 ≥ 9）。

现有代码已有高度相似能力可直接复用：
- 快进快出系列与半仓/卖点：`strategies/families/emoQuick.js`、`engine/sellHooks/emoQuickOut.js`
- 延时建仓 + 板块内选股：`engine/quickRaisedBlock.js`、`engine/rangeBacktest.js` 中 `pendingRaisedBuy` / `openFirstPosition`
- 选股门槛（涨停顺延/抗分歧≥9/3日涨幅/过热门槛）：`engine/pickBest.js`（按 strategyId 中的 `3d` 解析 3 日窗口）

## 设计决策（用户已授权自行决定）

1. 策略 id 沿用 `highest_` + `_gain` 命名，保证 `pickBestStock` 能解析出 3 日窗口、并自动继承过热门槛/涨幅领先顺延等 desc：
   `highest_3d_gain_key_block_attack_delay15 / 20 / 25 / 30`，名称「重点板块-进攻延迟15/20/25/30分钟」。
2. 新增策略标志 `keyBlockAttackDelay: n`（不占用 `keyBlockDays`，避免被路由到重点板块独立引擎）。
3. `emoQuickOut: true` 复用快进快出全部卖点与半仓、资金净流入阈值动态调节；买点仍走通用买点诊断。
4. 板块仅限「进攻」tag；窗口区间涨幅 = 目标桶 `avgChange` − 触发桶 `avgChange`，按差值降序；交集内选不出可买标的下，按差值顺延下一「进攻」板块；全部板块都选不出则本次不买（**不回退全量自选股**）。
5. 窗口校验：从触发桶之后到目标桶（含）的每个 5 分钟桶，要求 `fundFlow(t) − fundFlow(t−5) > 0` 且 `volume(t) − volume(t−5) > 0`；任一不满足 → 本次触发作废（不重试）。数据缺失按不通过处理。
6. 目标时点落在午休或 13:30 之后 → 本次触发不买（与现有延时建仓口径一致）。
7. 抗分歧沿用现有全局门槛 ≥ 9（用户口述「> 9」，与代码既有口径一致，不新增独立门槛）。
