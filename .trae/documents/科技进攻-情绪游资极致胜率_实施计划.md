# 科技进攻-情绪游资极致胜率 实施计划

## 一、Summary（需求与结论）

新增一个回测策略 **「科技进攻-情绪游资极致胜率」**（后端 id：`sci_attack_emo_win`），把两个已有策略融合为一个账户：

- A 风格 = **「3日涨幅最大&三日情绪-30快进快出」**（后端 id `highest_3d_gain_emoquick`，常规共享循环 + 快进快出半仓能力）
- B 风格 = **「情绪游资-极致胜率」**（后端 id `hot_money_extreme_win`，独立引擎 + 双腿结构：顺周期腿 + 逆周期腿，各半仓）

用户规则（原文）：
> 「如果当下是空仓，那么谁先触发买谁。当然如果说一个买了半仓，那么另外一个哪怕买点触发了也不能买剩下的半仓，只能先坚持做一种风格，等这一笔交易完全结束了之后再说下一次。如果是同时触发，那么快进快出的优先级更高。」

已确认三项语义（AskUserQuestion 回答）：
1. **仓位模型 = 风格独占整个账户**：账户仍为 2 个半仓槽，但由某一风格独占；该风格按其自身逻辑建仓（快进快出：快进快出情形首日半仓、次日补第二份；非快进快出情形首日即全仓。极致胜率：顺/逆两条腿各半仓）；期间另一风格被完全禁止；直到该风格全部平仓回到空仓，另一风格才解禁。
2. **极致胜率保持双腿结构**（顺周期腿 + 逆周期腿，逆周期腿不删除）。
3. **「同时触发」判定粒度 = 同一时间桶内**（同桶两风格买点均触发 → 快进快出优先；不同桶严格按桶先后）。

实现方式：新建一个独立回测引擎 `runFusedEmoWinBacktest`，内部维护 `styleLock`（`null` / `'emo'` / `'ew'`）状态机，逐桶先卖出、再买入；空仓桶内先评估快进快出（emo）买点，emo 未成交才评估极致胜率（ew）买点；锁定期间只允许当前风格继续建仓与平仓。

## 二、Current State Analysis（现状分析）

### 2.1 两套引擎的架构差异

| | 快进快出（`highest_3d_gain_emoquick`） | 极致胜率（`hot_money_extreme_win`） |
|---|---|---|
| 分发 | 走**常规共享循环**（`runRangeBacktest` / `runRangeBacktestMulti`） | 走**独立引擎** `runExtremeWinBacktest` |
| 日期源 | `getTrainingCampDates()` + `buildWindowAxis(..., 10)` 预热前移 | `getTrainingCampDates() ∪ getTechIndexDates()`（不依赖资金快照） |
| 选股 | `runBuyPointDiagnosis` + `withDualGateInfo` + `pickBestStock(..., 'highest_3d_gain_emoquick', ...)`（经 `selectors/delegates.js` 委派到 `highest_3d_gain` 并附 `emoQuickOut` 标注）+ `withResilienceGateInfo` | `buildExtremeWinPool` / `buildReverseLeaderPool` + 强度分/差劲分逐桶实时 |
| 持仓 | 普通 1 份；快进快出情形半仓（`twoBuy/leg/weight`，次日补第二份） | 2 腿（`splitLeg` A/B + `cycle` procyclic/counter），各 0.5 |
| 卖点 | `emoQuickOutSell`（次日 10:00 强卖 + -2% 止损 + 强卖豁免）+ `generalSellPositions`（通用 7 条件 + 盘中大跌强卖） | `scanLeaderPriceSell` 9 条 + 逆腿「上证 3 日线斜率盘中由负转正」+ 第 3 日尾盘 + 收盘抗分歧 < 6 |
| 收益 | `computeTwoBuyAccountReturn`（分批建仓口径）或逐笔复利 | 两腿各自复利后按 0.5 加权相加 |

### 2.2 关键约束（调研结论，决定实现方式）

1. **`pickBestStock` 按 strategyId 字符串解析选股口径**（[pickBest.js](file:///Users/xieyin/Desktop/盯盘工具/server/src/service/buySellBacktest/engine/pickBest.js#L16-L56)）：`gainMode = strategyId.includes('_gain')`、`days = /(\d+)d/`。新策略 id 若直接传入会走「窗口抗分歧」分支（错误）。→ **融合引擎的 emo 侧必须把 `'highest_3d_gain_emoquick'` 作为 strategyId 传入 `pickBestStock` / `withDualGateInfo` / `runBuyPointDiagnosis` 的口径来源**，这样 `selectors/delegates.js` 会自动委派到 `highest_3d_gain` 并挂 `emoQuickOut` 标注，与独立快进快出策略**完全一致**。
2. **`generalSellPositions` / `emoQuickOutSell` 依赖 `strategy.emoQuickOut === true`、`strategy.crashSell === true` 与 `pos.emoQuickOut.quickOut`**（[generalSell.js](file:///Users/xieyin/Desktop/盯盘工具/server/src/service/buySellBacktest/engine/sellHooks/generalSell.js#L23-L28)）。→ emo 侧需传入一个**合成策略视图** `emoStrategyView = { id: 'highest_3d_gain_emoquick', emoQuickOut: true, costLinePct: <融合策略的 costLinePct> }`，使 emo 腿的卖点行为与独立快进快出一致（含盘中大跌强卖）。
3. **`runRangeBacktestMulti` 目前未分发 `extremeWinMode`**（[rangeBacktestMulti.js](file:///Users/xieyin/Desktop/盯盘工具/server/src/service/buySellBacktest/engine/rangeBacktestMulti.js#L29-L37) 只过滤 `keyBlockDays / reverseLeaderMode / nBoardMode / volumeShareMode`）。worker（`--child`）与 `--strategies` 均走 `runRangeBacktestMulti`（[backtest-worker.js](file:///Users/xieyin/Desktop/盯盘工具/server/script/backtest-worker.js#L91-L112)），**因此新独立引擎必须在 multi 路径也加分发分支，并扩展 `regularIds` 排除条件**；同时计划顺带补上 `extremeWinMode` 的 multi 分发（同因，否则 worker 全量重跑时既有极致胜率会落入常规循环）。
4. **回测缓存按「策略 + 精确日期范围」文件名匹配**（`backtest_{strategyId}_{start}_{end}.json`）；`backtestReport.generateReport` 与 worker 均通过 `Object.keys(STRATEGIES)` **自动枚举**策略，注册即自动纳入，无需改枚举代码。

#### 结果组装

- `trades = sortTradesByBuyTime([...emoTrades, ...ewTrades])`，重新编号 `seq`。
- emo 腿成交（`twoBuy === true`）额外补 `splitLeg: leg === 1 ? 'A' : 'B'`、`positionMode: 'offense'`（便于前端双腿标签与 `BacktestReportModal` 渲染）；emo 全仓成交保持原字段（`weight: 1`）。
- `currentHoldings`：emo 期末持仓（按 `getPositionLegWeight` 折算 `weight` / `rawBuyReturn` / `buyReturn`，与 `rangeBacktest.js` L266-288 同）+ ew 期末持仓（照搬 `runExtremeWinBacktest` L652-664，`splitLeg` / `cycle` / `weight: 0.5`）。二者因互斥不会同时存在。
- `overallReturn = computeTwoBuyAccountReturn([...trades, ...currentHoldings.map(h => ({ ...h, returnRate: h.buyReturn ?? h.returnRate }))])`
  - 口径说明：`computeTwoBuyAccountReturn` 按「买入/卖出时刻区间是否重叠」分轮——两风格互斥（区间不重叠）→ **跨风格复利**；同一风格内的两份半仓（emo 补买、ew 双腿）时间重叠 → **轮内相加**。因为收益已按份权重折算（`weight`），这正是用户要的「逐份半仓、跨轮复利」账户口径，且与独立策略的账户口径可类比。
- 末尾 `attachBuyDayReturn(trades)` / `attachBuyDayReturn(currentHoldings)`（与两独立引擎一致）。
- 异常与早退：`!STRATEGIES[strategyId] || strategy.fusedEmoWinMode !== true` → `{ success:false, message }`；`rangeDates` 为空 → `{ success:false, message:'所选日期范围内无可回测交易日' }`。

## 四、Assumptions & Decisions（假设与决策）

1. **新 flag 命名 `fusedEmoWinMode`**（不复用 `extremeWinMode`，避免被 `extremeWinBacktest` 入口校验与 registry 排除逻辑误判）。
2. **新引擎独立实现**（不改造两个既有引擎的内部循环）：改造既有引擎需注入外部锁状态，回归风险更高；新建文件并通过导出 `buildPosition` / `buildRevPosition` 与复用全部公共模块，重复代码可控。
3. **emo 侧口径以 `'highest_3d_gain_emoquick'` 作为 strategyId 传入** `pickBestStock` / `withDualGateInfo` / `runBuyPointDiagnosis`（保证选股委派、双门禁、检查4 比例收紧与独立策略逐字节一致）；卖点侧使用合成 `emoStrategyView`（`emoQuickOut: true`）保证快进快出专属卖点 + 盘中大跌强卖生效。
4. **日期源采用 `getTrainingCampDates() ∪ getTechIndexDates()`**（同 `runExtremeWinBacktest`），并在此轴上构建 10 日预热窗口轴。差别：若某日仅存在于 tech_index（无回放数据），emo 侧所需数据缺失，该日整体按「无回放数据」记录 `skippedDates`（对 emo 侧无影响，因快进快出本来也只跑回放交易日）。
5. **整体收益口径采用 `computeTwoBuyAccountReturn`**（区间合并：重叠轮内相加、跨轮复利），与既有「两份半仓」账户口径一致；因两风格互斥，不会出现跨风格误相加。
6. **极致胜率双腿结构完整保留**（逆周期腿不删除）；融合策略内不再保留「水平互补择时」的自由度——两条腿都在 `styleLock === 'ew'` 时才允许建仓，`styleLock === 'emo'` 时两条腿都被禁止。
7. **「同时触发」= 同桶判定**：单桶内先评估 emo、后评估 ew；emo 本桶成交即不再评估 ew。若 emo 买点诊断 `allPassed` 但选股无可用标的（全涨停等），视为 emo 本桶未成交，ew 可继续评估。
8. **顺带修复 `runRangeBacktestMulti` 缺失的 `extremeWinMode` 分发**（一致性必需，避免 worker 全量重跑覆盖既有极致胜率缓存）。此改动不改变单策略路径行为。
9. **待重跑缓存**：新增策略与修改后的 desc/分发都需 `backtest-worker` 重跑才进入回测报告；既有 `backtest_results/backtest_*.json` 为旧口径产物。
