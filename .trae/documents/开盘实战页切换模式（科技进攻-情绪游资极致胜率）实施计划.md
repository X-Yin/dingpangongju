# 开盘实战页「切换模式」实施计划（科技进攻 / 情绪游资-极致胜率）

## 一、Summary

在开盘实战页「自选股 · 3日涨幅前十」卡片标题栏新增下拉框「切换模式」，提供两个模式：

- `tech_attack`（科技进攻，默认）= 现状，全部逻辑不变；
- `hot_money_extreme_win`（情绪游资-极致胜率）= 与回测页「情绪游资-极致胜率」策略一致的买卖点。

模式为**全局状态 + localStorage 持久化**（用户已确认）。切换后联动：

1. 该卡片标题变为「情绪游资-龙头列表」，数据源换成 `POST /hot_money_leader_list`，列表换成「除 `强度分 − 差劲分 ≥ 30` 与「上证 3 日线斜率为正」以外，其余买点条件全部满足」的个股；
2. 「买点诊断」卡片与「卖点诊断」卡片的检查项集合切换为极致胜率口径；
3. 全局悬浮组件 `FloatingStockPosition`（所有页面）内的买/卖点诊断同样跟随模式切换；
4. 飞书通知卡片在极致胜率模式下只推「完整买点股」（同时满足 `delta ≥ 30` 且上证 3 日线斜率 > 0 的龙头列表个股，且未封涨停），无则不推。

用户已确认的三个决策：
- 卖点条件 = **完整龙头战法 9 条**；
- 龙头列表展示**全部达标股**，飞书**只推完整买点股**，没有则不推；
- 模式**全局生效 + 持久保存**。

#### B2. 新增 live 服务 `server/src/service/hotMoneyExtremeWin.js`（新文件）

依赖：`./buySellBacktest/engine/extremeWinPool`、`./buySellBacktest/engine/extremeWinScores`、`./buySellBacktest/engine/indexGate`、`./buySellBacktest/deps`、`./buySellBacktest/diagnose/sellPoint`（`calculateReplayResilience`）、`./buySellBacktest/engine/leaderSellMinute`、`../utils`（`batchParallel`、`isTradingDay`、`getPrevTradingDay`）、`./stock`（`getSingleStockData`）。

交易日回退：与 `getBuyPointChecks` 一致——`targetDate` 缺省时用 `dayjs()`，非交易日回退 `getPrevTradingDay()`。

**`fetchExtremeWinContext(targetDate)`（内部）**：返回 `{ dateStr, isAfterClose, minute, indexSlope, pool, rows }`：

1. `pool = await buildExtremeWinPool(dateStr)`；
2. `crossDates = await getPastTradingDates(dateStr, DEATH_CROSS_WINDOW)`，对池内每只 `batchParallel(..., 6)` 并发 `computeCrossInfo(code, crossDates)`；
3. 取当前分钟 `minute`：对每只股票 `loadTlinePoints(code, dateNum)`，`minute = points.length ? points[points.length-1].minute : null`；`isAfterClose`（`isAfterMarketClose()`）为真或已过 15:00 时按 `CLOSE_MINUTE=1500` 口径；
4. 逐股按 `minute` 口径计算 `diff = diffAtMinute(points, preclose, code, minute, avg3Vol)`、`strength = strengthAtMinute(t, minute, code, idxT.points)`（`avg3Vol` 取自 `stockPriorAvgVolume`，与引擎同源）、`delta = round2(strength - diff)`；
5. `indexSlope = await getIceMa3SlopeIntraday(dateStr, minute || 1500)`；
6. 每只行记录：`{ code, stockName, board, lianbanCount, preclose, px, change, aRaw, isLimitUp, diffScore, strengthScore, delta, crossInfo: { crossDate, hitCount, prevDayDelta, prevDayStrength, prevDayVolumeOk }, listPassed, buyPointHit }`。

**达标判定（与引擎口径一一对应）**：

- `crossPassed = crossInfo.hasCross && !crossInfo.consumed && crossInfo.prevDayVolumeOk`（死叉 + 未被消耗 + 上日放量门禁）；
- `gatePassed = crossInfo.prevDayStrength == null || crossInfo.prevDayStrength <= PREV_STRENGTH_GAP_GATE || aRaw >= OPEN_GAP_MIN_PCT`；
- `listPassed = crossPassed && gatePassed`（= 池筛选 + 买点前置 + 竞价门禁，即用户要求的「除 delta≥30 与上证斜率>0 之外全部满足」）；
- `buyPointHit = listPassed && delta >= DELTA_MIN && indexSlope > 0`。

**`getExtremeWinBuyPointChecks(targetDate, refresh, force)`（导出）**：返回结构与科技模式完全一致，便于前端复用：

```js

```

- 取展示标的 `candidate = rows.filter(listPassed && !isLimitUp).sort(by delta desc)[0] || rows.filter(listPassed && !isLimitUp)[0] || null`（优先按 delta 降序取第一个未涨停者；无则取 `listPassed` 首行；仍无则用池内首个），`checks` 7 项与 `buildPosition` 的 id/title 一一对应（文案按实时值填充）：
  1. `extreme_win_pool`：passed = `poolCount > 0`，value = `龙头池 {poolCount} 只`；
  2. `extreme_win_cross`：passed = `crossPassed`，value = 死叉日 / 命中次数 / 上日 delta 与放量比；
  3. `extreme_win_prev_strength_gap`：passed = `gatePassed`，value = 上日强度分 / 竞价高开；
  4. `extreme_win_diff`：passed = true（信息项），value = 差劲分分项；
  5. `extreme_win_strength`：passed = true（信息项），value = 强度分分项；
  6. `extreme_win_threshold`：passed = `delta >= DELTA_MIN`，value = `强度 − 差劲 = delta`；
  7. `extreme_win_index_slope`：passed = `indexSlope > 0`，value = 上证 3 日线斜率。
- `allPassed = rows.some(r => r.buyPointHit)`；`passedCount` = `checks.filter(passed).length`；`totalCheckCount = 7`；
- 无候选时仍返回 7 项（未通过）与 `conclusion: '龙头池当前无满足条件的标的，请耐心等待。'`；
- 命中时 `conclusion: '龙头池出现完整买点标的（强度分 − 差劲分 ≥ 30 且上证 3 日线斜率为正），可关注买入时机。'`

**`checkExtremeWinSellPointDetailed(code, costPrice, buyDate)`（导出）**：返回与 `checkSingleStockSellPoint` 同构：

```js
{ success, isSell, reasons, stockName, tradeDate, conditions, conclusion, detail: { closePrice, change, resilienceScore, minute } }
```

- `conditions` 9 项（`{ name, satisfied, exempted, pending, pendingMinutes, detail }`），口径对应用户确认的「完整龙头战法 9 条」：
  1. `跌破成本线 -5%（即时）`：现价 < `costPrice × 0.95`（`costPrice` 缺省时从 `getStockPosition()` 读取，与现 `checkSingleStockSellPoint` 一致）；
  2. `盘中分时跌幅 ≤ -5%`：较昨收；
  3. `较开盘价下挫 5 个点`：较当日开盘价 ≤ -5%；
  4. `单分钟跳水 ≥ 3 个点`：相邻分钟跌幅 ≤ -3%，含「上一分钟自身涨幅 > 2% 则豁免」；
  5. `持仓股跌停`：较昨收 < -9%；
  6. `高位放量大阴线`：当日最高回落现价 > 8% 且现价 < 开盘；
  7. `持仓第 3 日未拉开 +10%`：`buyDate` 起算第 3 个交易日且尾盘（≥14:57）现价较成本 < +10%（非第 3 日则 `exempted`）；
  8. `竞价低开 < -5%`：当日首分钟较昨收；
  9. `当日收盘抗分歧指数 < 6`：`calculateReplayResilience`（收盘口径；未到收盘则 `pending`）。
- 分时数据统一走 `loadTlinePoints(code, tradeDateNum)`；`isSell = conditions.some(c => c.satisfied)`；买入当日（`buyDate === 今日`）时前端已自行跳过，后端无需特殊处理（保持与现有卡片一致的返回结构）。
- 该函数独立实现，**不调用** `buySellDiagnose.checkSellPointDetailed`（口径不同）。

## 四、Assumptions & Decisions

1. 模式值：`tech_attack`（默认）/ `hot_money_extreme_win`；存储键 `ob_strategy_mode`，全局共享 + localStorage 持久化（用户确认）。
2. 「龙头列表」= 池筛选 + 死叉前置（含上日放量门禁）+ 竞价低开门禁全部满足的个股，按 `delta` 降序（用户确认）；`delta ≥ 30` 与上证斜率 > 0 不参与列表筛选，仅作为「完整买点」判定。
3. 飞书只推完整买点股（`buyPointHit === true` 且未涨停，取前 3），无则不推（用户确认）。
4. 卖点条件 = 完整龙头战法 9 条（用户确认）；成本线止损取 `-5%` 即时（与极致胜率策略一致，非通用龙头战法的连续 5 分钟）。
5. 极致胜率买点诊断卡片 = 7 项检查，`allPassed` = 龙头列表中存在完整买点标的。
6. 非交易时段：回退最近交易日；分时不足时对应条件返回「未通过 / 数据不足」，不产生 false-positive；行情已收盘时按 1500 口径计算。
7. 不新增 Context/Provider，沿用模块级 store + CustomEvent（与仓库现有风格一致）。
8. 极致胜率的 live 计算与回测共享 `extremeWinPool.js`（同一份常量/函数），避免口径漂移；性能用 `batchParallel` 并发 6~8，`tlineCache` 由 `extremeWinScores` 进程内缓存，日期变更时按需 `clearTlineCache()`。
9. 不改动 `buySellDiagnose.js` 的既有科技进攻逻辑（仅在 `index.js` 按 `mode` 分流）。
