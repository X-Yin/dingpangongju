# 新增回测策略：情绪游资-赔率尚存&胜率提高-n 板定龙头

## Context（背景与目标）

用户要求在买卖点回测页面新增一个「情绪游资」类策略族，n = 1/2/3 共 3 个变体：

- **买点**：上证指数 3 日线斜率由负转正时出手；取**上一交易日** lianbanSnapshot 中**涨停数排名前三**的板块（**涨停数必须 ≥ 5**，否则宁缺毋滥直接跳过），在这些板块里挑 **n 板（lianbanCount === n）** 个股；要求当下**抗分歧分数 > 11** 才买；多只符合时买**当下分时涨幅最大**的一只；已涨停的顺延到下一只；一只都没有则本次跳过、不补买。
- **卖点**（持仓次日起，任一先触发即卖）：① 当日抗分歧分数 < 9（尾盘卖）② 收盘价跌破 5 日线（尾盘卖）③ 高位放量大阴线（尾盘卖）④ 下影线 ≥ 实体 2 倍（14:55 卖）⑤ 上证指数斜率由正转负（尾盘卖）⑥ 跌停 ⑦ 跌破成本线 -2% 止损。

信号与「顺周期情绪游资」（`hot_money_ice_*`）同源，因此**买点触发时点沿用顺周期情绪游资口径**（已与用户确认）：要求前一交易日收盘口径斜率为负（只认一次新的转正事件），当日 **9:40 及以后**才执行买入（等分时点数足够算抗分歧）。卖点 ②③ 采用**尾盘统一判定**（已确认），③ 沿用通用条件 2 的「最高回撤 > 8% 且现价 < 开盘价」口径、**不额外校验量能**（已确认）。

因候选股选择与卖点判定都与现有引擎差异较大，采用**新建独立引擎**（与 `keyBlockBacktest` / `emoQuick` 同模式），最大化复用现有数据层与工具函数。

## 策略命名

| 字段 | 值 |
| --- | --- |
| id | `hot_money_leader_1b` / `hot_money_leader_2b` / `hot_money_leader_3b` |
| name | `情绪游资-赔率尚存&胜率提高-1板定龙头`（2/3 同理） |
| 标记 | `leaderBoardN: 1/2/3`、`costLinePct: 2` |

> 不使用 `keyBlockDays` 字段，避免误路由到 `runKeyBlockBacktest`。

## 后端改动

### 1. 数据层 `server/src/service/keyBlockData.js`
复用现有 `readLianbanSnapshot` / `getPastTradingDates`，新增：

- `getLeaderBoardCandidates(prevDateStr, boardN, topN = 3, minCount = 5)`：读上一交易日快照，`themes` 按 `count` 降序（并列按 `rank` 升序）→ 过滤 `count >= minCount` → 取前 `topN` 个板块 → 收集其中 `lianbanCount === boardN` 的个股（`marketCode || code`），按 code 去重，返回 `[{ code, name, board, lianbanCount }]` + 命中的板块明细（供买入明细展示）。
- `scanLeaderBoardCodesInRange(rangeDates, boardNs)`：预扫描回测区间内所有可能的 n 板候选 code，供一次性预拉日K（卖点 MA5 需要日K）。
- `getStockMaOn(code, dateStr, n)`：用 `barsCache` 计算截至某交易日（含当日）的 n 日均线（收盘价口径）。

### 2. 策略描述 `strategies/descs.js`
新增 `LEADER_BOARD_DESC(n)`，完整描述买卖规则（与用户口径逐条对应）。

### 3. 策略定义 `strategies/families/leaderBoard.js`（新文件）
按 `keyBlock.js` / `ice.js` 的写法，导出 3 个策略对象（id/name/desc/leaderBoardN/costLinePct）。

### 4. 注册 `strategies/registry.js`
- `...leaderBoardStrategies` 合并进 `STRATEGIES`。
- `isCycleFilterStrategy` 追加排除条件 `s.leaderBoardN == null`（与 ice/keyBlock 一致，不给本策略自动追加顺周期过滤文案）。

### 5. 独立引擎 `engine/leaderBoardBacktest.js`（新文件）
`runLeaderBoardBacktest(startDate, endDate, strategyId, onProgress)`，参考 `keyBlockBacktest` 的冰点路径与结果组装：

- **日期轴**：并入 `getTechIndexDates()`（与 ice 一致，补上缺资金快照的交易日），升序；缺失资金快照日期用 `loadTrainingCampData(dateStr, { allowMissingFund: true })` 兜底。
- **预热**：预拉候选股日K（`scanLeaderBoardCodesInRange` → `ensureBarsForCodes`），并预构建上证 3 日线斜率序列（`ensureIndexMa3SlopeSeries(ICE_SIGNAL_INDEX_CODE)`）与首日前一收盘斜率初值（复用 ice 逻辑）。
- **状态机（复用 ice 顺周期口径）**：逐桶计算 `getIceMa3SlopeIntraday`，追踪 `lastSlopeSign/Value`，识别由负转正；仅当「前一日收盘口径斜率为负」时该转正才算有效买点（`getIceMa3Slope(dateAxis[diA-1])`）；`pendingEntry` 当日≥9:40 且仍空仓时建仓，候选全不合格则本桶不买、后续桶继续重试；**次日不再补买**；斜率由正转负作废未成交意图。
- **买入 `openPosition`**：
  1. `getPastTradingDates(dateStr, 1)` 取上一交易日 → `getLeaderBoardCandidates(prevDate, n)`（进程内按日期缓存）。
  2. 逐候选取当日分时（`getSingleStockTlineDataByDate`），算截至桶时点的 `changePct` 与抗分歧分数（`calculateReplayResilience` + `iceResilienceIndexCode` 市场映射：主板 sh000001 / 创业板 sz399006 / 科创板 sh000688）；抗分歧需 **> 11**。
  3. 过滤：`EXCLUDED_CODES`、`isOscExcluded`、桶时点涨停（`isLimitUpAtBuy`）；涨停者顺延。
  4. 排序：按 `changePct` 降序，取第一只满足者；全不合格本次跳过（不重试到次日）。
  5. 写入 `position`（weight 1 全仓，`buyChecks` 明细：斜率门禁 / 上一交易日涨停前三板块与 count / n 板候选 / 抗分歧 > 11 / 涨停顺延 / 选股口径），买入价取桶时点分时价。
- **卖出**：持仓且 `dateStr > buyDate` 时，用当日分时（`getSingleStockTlineDataByDate`）+ 日K MA5（`getStockMaOn`）判 7 条件：
  - 即时桶：⑥ 跌停（主板 ≤ -9.5%、创业/科创 ≤ -19%）⑦ 跌破成本线 -2%（含「竞价低开自救窗口」+ 逐分钟回溯精确成交，逻辑照搬 `keyBlockBacktest` 冰点分支）。
  - **14:55 桶统一**：① 抗分歧 < 9 ② 现价 < MA5 ③ 最高回撤 > 8% 且现价 < 开盘价 ④ 下影线 ≥ 2×实体 ⑤ 上证 3 日线斜率由正转负（`lastSlopeSign > 0 && 当前 < 0`）。命中任一按 14:55 分时价卖出。
  - `sellReason` 标注命中条件与具体数值。
- **结果组装**：与 ice 分支一致（`type:'single'`、`overallReturn` 复利、`attachBuyDayReturn`、`calcDrawdownStats`、`currentHolding` 用回放收盘价 / 日K 收盘兜底估值）。

### 6. 路由
- `engine/rangeBacktest.js`：`runRangeBacktestInner` 顶部、`keyBlockDays` 判断之前，新增 `if (STRATEGIES[strategyId]?.leaderBoardN != null) return runLeaderBoardBacktest(...)`。
- `engine/rangeBacktestMulti.js`：`keyBlockIds` 旁增加 `leaderIds`，逐个走 `runLeaderBoardBacktest`（保持多策略入口一致）。

### 7. 依赖 `deps.js`
补充导出 `getLeaderBoardCandidates`、`scanLeaderBoardCodesInRange`、`getStockMaOn`。
