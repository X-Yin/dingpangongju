# 情绪游资-成交量占比 策略实现方案

## Context（背景与目标）

用户要在回测功能（前端入口 `盯盘工具/src/pages/backtest/index.jsx` 内嵌的 `BacktestDrawer`）中新增一个**情绪游资类**策略「情绪游资-成交量占比」，N 取 **2 / 3 / 5**，即 3 个独立策略。

需求原文：
> 选股：去成交量占比里面筛选截止到上个交易日 3 日线斜率为正的板块，然后筛选里面斜率最陡峭的前三个板块（剔除半导体，液冷，光通信，存储芯片，pcb），然后去这几个板块的 json 文件中找到所有个股。然后再和最近五个交易日的所有连板个股进行交叉过滤。找到其中所有重叠的个股。买入这些个股中 n 日涨幅最大的个股，一字板顺延下一个个股，只能买当日分时涨幅大于 -5% 的，抗分歧指数大于 9 的个股
> 买点：等到 9:40 之后再买
> 卖点：当该个股所属板块的成交量占比的三日线斜率截止到上个交易日变成负数的时候，第二天开盘就卖出
> N 取 2 3 5

已与用户确认的口径：N 日涨幅窗口含买入当日**当前桶**分时涨幅复利（同 `computeWindowGain`）；「一字板顺延」= 买入时点该股正处涨停则顺延下一只；抗分歧阈值 ≥ 9；仓位 = **半仓单持仓（权重 0.5、逐笔复利）**；**买点自 9:40 起在后续桶持续重试直到买进（当日不买则次日再看）**；**卖点板块 = 该股命中的多个前 3 板块中任一斜率最先转负者即触发**。

该策略与现有策略差异较大（候选池来自「板块成交量占比 + 板块成分股 ∩ 连板股」，而非自选股），且买卖点不依赖平台回放数据/资金快照，因此**新建独立回测引擎**，仿 `engine/nBoardBacktest.js`（同为半仓单持仓独立引擎）实现。

## 策略定义

3 个策略 id（沿用现有 `hot_money_*` 命名风格）：

| id | 名称 | 标志位 |
| --- | --- | --- |
| `hot_money_volume_share_2d` | 情绪游资-成交量占比2日 | `volumeShareMode: true, volumeShareDays: 2` |
| `hot_money_volume_share_3d` | 情绪游资-成交量占比3日 | `volumeShareMode: true, volumeShareDays: 3` |
| `hot_money_volume_share_5d` | 情绪游资-成交量占比5日 | `volumeShareMode: true, volumeShareDays: 5` |

引擎通过 `strategy.volumeShareDays` 区分 N，一个引擎文件服务 3 个策略。

## 复用的数据源与工具（均已存在，不改）

- 板块成交量占比：`server/src/service/板块成交量占比计算/category_amount_money.js`
  - `getBlockCategoryRatio(null, null)` → `{ [分类名]: [{date:'YYYYMMDD', ratio, money, totalAmount}, ...] }`（按日期升序）。板块占比 = 板块成交额 / 全市场总成交额 × 100。
  - `CATEGORY_NAMES` 含 14 类；**排除半导体、液冷、光通信、存储芯片、pcb 后剩 9 类**：传媒、农业、消费、医药、电力、锂电池、商业航天、军工、机器人。
- 板块成分股：`server/src/data/东方财富板块成分股汇总/{分类}.json` → `[{code:'000032', name:'深桑达Ａ'}, ...]`，`code` 为**无前缀 6 位纯数字**。
- 连板数据：`getRecentMultiLianbanStocks(dateStr, lookbackDays, minBoardCount)`（从 `../deps` 引入）→ `{ stocks: [{code:'sh603197', name, lianbanCount, ...}] }`，`code` 为**带前缀**，lookback **严格不含当日**，产自 `lianbanSnapshot/{YYYYMMDD}.json`。
- 日K/涨幅：`../deps` 的 `getStockCloseOnOrBefore`、`ensureBarsForCodes`、`stockDailyChange(code, dateStr)`（相邻收盘环比，返回百分数）、`getPastTradingDates(dateStr, lookbackDays)`（严格不含当日、升序、基于创业板指交易日历）、`batchParallel`。
- 分时：`engine/extremeWinScores.js` 的 `loadTlinePoints(code, dateNum)` → `{preclose, points:[{minute,lastPx,change,vol}]}`（`code` 带前缀、`dateNum` 为数字 YYYYMMDD；进程内缓存）、`clearTlineCache()`、`round2()`。
- 抗分歧：`diagnose/sellPoint.js` 的 `calculateReplayResilience(stockLine, indexLine, code)`；跟踪指数规则同 `engine/replayData.js` 的 `calcResilienceAtMinute`：**`sh688` → 科创50 `sh000688`，其余 → 创业板指 `sz399006`**。
- 仓位/统计：`engine/twoBuy.js` 的 `TWO_BUY_LEG_WEIGHT=0.5`、`computeTwoBuyAccountReturn(legs)`；`utils/tradeStats.js` 的 `attachBuyDayReturn`、`calcDrawdownStats`、`sortTradesByBuyTime`。
- 涨停/一字板阈值：主板（60/00）≥ 9.5%；创业板（30/301）/科创板（688）≥ 19%（同 `extremeWinScores.limitUpThresholdOf`、`replayData.isLimitUpAtBuy`）。
- 排除股票：`../constants` 的 `EXCLUDED_CODES`（源杰科技、联讯仪器）。
- `fs` / `path`（从 `../deps` 引入）用于读板块成分股 JSON。

> `deps.js` 已导出上述 `deps` 项，**无需修改**。`getBlockCategoryRatio` 未在 deps 中，由新引擎直接 `require('../../板块成交量占比计算/category_amount_money')`。

## 新增引擎：`server/src/service/buySellBacktest/engine/volumeShareBacktest.js`

导出 `runVolumeShareBacktest(startDate, endDate, strategyId, onProgress)`。纯日期驱动，**不依赖 `campData`**。日期序列 = `getTrainingCampDates()` 过滤 `[startDate, endDate]` 升序。

**启动一次性准备**
1. `getBlockCategoryRatio(null, null)`（try/catch；缺文件则返回 `{success:false, message}`），得到各类占比序列；按 9 个候选分类建 `Map<date, ratio>`。
2. 为每类构建按日期升序的 `{dates, ratios}` 数组。
3. 板块成分股：读 9 个分类的 `{分类}.json`，建 `Map<分类, Set<bareCode>>` 与 `Map<分类, Map<bareCode, name>>`。

**MA3 斜率工具**（占比口径，收盘序列）
```
// 截止到 refDateStr（含）的 3 日线斜率 = (r[i] - r[i-3]) / 3，i = 最后一个 date <= refDateStr 的索引；i<3 返回 null
blockSlope(category, refDateStr)
```
选股用 `refDateStr = getPastTradingDates(D,1)[0]`（上一交易日 T-1）；若 T-1 无占比数据则回退取最后一个 `< D` 的日期。

**逐日 D 循环**
1. **卖点（隔夜持仓，且 D > buyDate）**：对 `position.categories`（买入时该股命中的前 3 板块集合）逐一计算截止 `T-1` 的斜率；**只要任一板块斜率 `< 0`** → 在该日**首个分时点（开盘）**按开盘价卖出，记录 trade（`weight=0.5`、`rawReturnRate` 为个股真实收益、`returnRate = rawReturnRate×0.5`），置 `position=null`、`soldThisDate=true`。
   - 说明：买入当日 `T-1`（= buyDate 前一日）斜率为正（选股前提），故买入当日不会触发卖点；仅次日起可能触发 —— 与「第二天开盘就卖出」一致。
2. **选股（当日无持仓、且当日未卖出）**：**自 9:40 起逐桶重试**。遍历 `bucket.minute >= 940`（且 `<= 1130`，早盘窗口）的桶，一旦买进即停止；当日所有桶均无合格候选则不买（次日再看）。
   每个桶在该桶分钟 `M` 上重算候选快照并重排：
   - **① 板块（每日一次，`T-1` 口径）**：对 9 个候选分类算 `blockSlope(cat, T-1)`，取 `> 0` 者按斜率**降序**取前 3（不足 3 取全部）。
   - **② 成分股 ∩ 近 5 日连板（每日一次）**：`getRecentMultiLianbanStocks(D, 5, 1)` → 每只 `marketCode` 去前缀得 bareCode；与「前 3 板块成分股 bareCode 全集」求交集。交集个股记为候选，`categories` = 其命中的全部前 3 板块（卖出时任一转负即卖）；`code` 用带前缀 marketCode；剔除 `EXCLUDED_CODES`。
   - **③ 该桶分时现算**：`batchParallel` 拉取候选 `loadTlinePoints(code, D)`（进程内缓存，跨桶复用）。每只算 `todayChange` = `minute<=M` 最后一点的较昨收涨幅、`curPx` = 该点 lastPx、`curLimitUp` = `todayChange >= 涨停阈值`（主板 9.5% / 创·科 19%）。
   - **④ N 日涨幅排名（每桶重排）**：`winDates = [...getPastTradingDates(D, N-1), D]`；`gain = computeNDayGain(code, winDates, todayChange)`（复利口径，见下）；按 gain **降序**（null 排最后）。
   - **⑤ 顺延筛选**（按排名依次判断，命中即按 `curPx` 买入）：
     - **一字板/涨停顺延**：该桶 `curLimitUp` → 跳过、顺延下一只。
     - **当日分时涨幅 > -5%**：`todayChange <= -5` → 跳过。
     - **抗分歧 ≥ 9**：按跟踪指数现算 `calculateReplayResilience(stockLine≤M, indexLine≤M, code)`（指数 `sh688`→`sh000688`，其余→`sz399006`）；`< 9` 或数据不足 → 跳过。
     - 通过者 → 按该桶分时价买入，`weight=0.5`，记录 `position`（含 `categories`、`buyDi`）；同桶只买 1 只。

`computeNDayGain`（本地实现，复刻 `replayData.computeWindowGain` 复利口径，但数据源改 `stockDailyChange`）：
```
let prod = 1;
for i in winDates: ch = (i === last ? todayChange : stockDailyChange(code, winDates[i]));
                  if (ch == null || !isFinite(ch)) return null;
                  prod *= 1 + ch/100;
return (prod - 1) * 100;
```

**结果组装**（结构对齐 `nBoardBacktest`）：`type:'single'`、`trades`（`sortTradesByBuyTime`）、`currentHolding`（期末未平仓按 `getStockCloseOnOrBefore(code, 最后回测日)` 估浮盈、×0.5）、`summary`（`tradeCount`/`winCount`/`winRate`/`calcDrawdownStats`/`overallReturn`=`computeTwoBuyAccountReturn`）。每笔 trade/持仓含 `buyReason`+`buyChecks`（逐项明细：板块斜率排名、交集候选、N 日涨幅排名、一字板、分时 >-5%、抗分歧 ≥ 9、半仓），并在结束前对 trades/持仓 `attachBuyDayReturn`。每日 `clearTlineCache()` 重建分时缓存控内存；`seenStocks` 汇总候选股。

## 验证

1. **语法**：`node --check` 三个后端新/改文件；前端 `npx eslint` 或构建（`npm run build`）。
2. **短区间回测**：用现有 worker 或直接脚本调用 `runVolumeShareBacktest('20260801','20260901','hot_money_volume_share_3d')`，确认：
   - 有正常成交、`weight=0.5`、`overallReturn` 合理；
   - `buyChecks` 明细齐全；
   - 抽查某笔：T-1 板块斜率 > 0 且属前 3、与近 5 日连板股交集、买入时点非涨停、分时涨幅 >-5%、抗分歧 ≥9；卖出日 = 持仓所属任一板块 T-1 斜率转负后的次日开盘。
3. **前端**：打开回测抽屉选到新策略，确认下拉选项、分类 Tag、买卖规则说明、策略专属说明正常渲染；跑一次回测确认报告展示半仓折算提示。
