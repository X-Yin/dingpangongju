# 实施计划：新增「N日涨幅最大-成交量占比」策略 + 成交量占比图坐标轴刻度修复

## Context

用户提出两项需求：

1. 在回测页（`盯盘工具/src/pages/backtest/index.jsx`，实际内嵌 `BacktestDrawer`）新增 4 个独立策略「2/3/4/5 日涨幅最大-成交量占比」：
   - 板块层：从 `东财板块到本地板块map.json` 的 33 个一级板块中，选出「上一交易日 T-1 成交量占比创过去 10 个交易日最大值」的板块；若多个并列，取 `占比(T-1) - 占比(T-2)` 差值最大者（资金流入最多、最可能是主线）。
   - 个股层：在该板块的沪深主板（60/00）、创业板（30）、科创板（68）成分股中，按「最近 N 日涨幅」（复利口径，含当日 9:40 分时涨幅）排序取前 5 只；只在 **9:40 这一个时间点**检查，买入排名最高且满足「9:40 未涨停 + 分时涨幅 > 0 + 现价 > 当日开盘价」的一只；当日无合格则跳过。
   - 卖点：与现有「N日涨幅最大」完全一致（通用 7 条件卖点 + 盘中大跌 -7% 强卖）。全仓单持仓。
2. `MainFund` 页的成交量占比图（组件 `BlockVolumeRatio`）右侧 Y 轴刻度统一保留一位小数，消除 `0.9000000000001%` 类浮点误差。

用户已确认：
- 买点「只看 9:40 一个时间点，不逐桶重试」。
- N 日涨幅**含当日 9:40 分时涨幅**（与现有策略一致）。
- 涨停过滤**仅看买入时点（9:40）是否涨停**。
- 选股采用**完全精确**口径（不预筛），但**不要新增冗余缓存**，控制磁盘/内存占用。
- 前 5 名中若多只满足条件，**买排名最高的一只**。

## 二、后端：新增独立回测引擎

新建 `server/src/service/buySellBacktest/engine/gainVolumeShareBacktest.js`，导出 `runGainVolumeShareBacktest(startDate, endDate, strategyId, onProgress)`。

参考模板：
- `engine/keyBlockBacktest.js`：逐日 `loadTrainingCampData` + 时间桶循环 + 非自选股持仓的合成桶数据（`buildKeyBlockSyntheticDay` / `buildKeyBlockSyntheticBucketEntry`）+ 结果组装。
- `engine/volumeShareBacktest.js`：板块占比序列读取、`computeNDayGain`（复利）、涨停阈值、`loadTlinePoints` / `clearTlineCache`、全仓单持仓结果结构。

### 关键实现点

1. **数据加载（进程内、每次回测运行一次，不落新盘）**
   - `BOARD_DIR = path.resolve(__dirname, '../../../data/东方财富板块成分股汇总')`。
   - 读 `meta/东财板块到本地板块map.json` 的 33 个 key。
   - `getBlockCategoryRatio(null, null)` 取各一级板块 `[{date, ratio}]`，按日期升序；只保留 map 的 33 个 key（忽略 `_blocks`）。
   - 成分股 `{板块}.json` 按需读取（只读当日命中的板块），记录 `Map<bareCode, name>`。

2. **板块选择（每日以 D 的 T-1 为准）**
   - `getPastTradingDates(dateStr, 10)` 得到 T-10…T-1。
   - 对每个一级板块：取 `date <= String(T-1)` 的最后 10 条占比记录；**要求最后一条日期 === String(T-1)** 且至少 2 条，否则该板块不参与。
   - 若 `ratio[T-1] >= max(这 10 条)`（占比已保留 4 位小数，直接比较）则该板块「创近 10 日新高」。
   - 并列时取 `ratio[T-1] - ratio[T-2]` 最大者；仍并列按 map 原始顺序取第一个。
   - 无板块命中 → 当日不买（记录 skippedDates 原因）。

3. **候选过滤**
   - 成分股 bare code 仅保留 `/^(60|68|00|30)/`，转完整代码：`6→sh`、`0/3→sz`；剔除 `EXCLUDED_CODES`。
   - `await ensureBarsForCodes(候选完整代码集合)`（全局 bars 缓存，跨日复用，墙面只拉一次）。
   - 先按日 K 过滤掉「前 N-1 个交易日涨幅数据缺失」的股票（`stockDailyChange` 返回 null），减少无效分时拉取。

4. **9:40 分时与排名（完全精确，不加新缓存）**
   - 每天开始 `clearTlineCache()`，控制进程内存。
   - 对剩余候选 `batchParallel(..., 8)` 调 `loadTlinePoints(code, dateNum)`（复用 `engine/extremeWinScores.js`）。
   - `preclose` 缺失或无 ≤9:40 的点 → 跳过。
   - `openPrice` = 当日分时第 1 点 `lastPx`；`px940` = minute ≤ 940 的最后一点；`todayChange = (px940/preclose-1)*100`。
   - N 日涨幅：`computeNDayGain(code, [...prevDates, dateStr], todayChange)`（复利，最后一位用 9:40 分时涨幅；`prevDates = getPastTradingDates(dateStr, N-1)`）。
   - 按涨幅降序取前 5。
   - 依次检查前 5：① 9:40 涨幅 < 涨停阈值（主板 9.5 / 创·科 19）② `todayChange > 0` ③ `px940 > openPrice`。第一只通过者买入，价格 = `px940`。

5. **买点时间**
   - 只处理 `minute === 940` 的时间桶；若该日无 940 桶，取 minute > 940 的第一个桶（仍属「9:40 之后」），当日无桶则跳过。不逐桶重试。

6. **持仓与卖点（复用通用逻辑）**
   - `positions = [position]`（全仓，weight = 1，`costLinePct` 缺省 → `runSellPointDiagnosis` 默认 -2%）。
   - 当日若已有隔夜持仓：按 `keyBlockBacktest.js` L457–472 的方式，若持仓股不在自选回放数据中，用 `buildKeyBlockSyntheticDay` + `buildKeyBlockSyntheticBucketEntry` 生成 `sellBuckets` / `sellReplayStocks`。
   - 逐桶调用 `generalSellPositions({ positions, strategy, bi, replayStocks: sellReplayStocks, timeBuckets: sellBuckets, dateStr, dateDisplay, singleTrades: trades })`（自带 T+1、通用 7 条件、`crashSell` 盘中大跌 -7%）。
   - 卖出后 `positions` 清空 → `position = null`；当日 9:40 桶若尚未来到且已空仓，允许按买点规则再买（与通用策略一致）。
   - 无持仓的日子不构建 `buildReplayStocksWithTline`（它会对全部自选股拉分时，避免无谓开销）。

7. **结果结构**（对齐 `type:'single'`）
   - `trades` 由 `generalSellPositions` 直接写入（含 buyReason / buyChecks / sellReason / returnRate）。
   - `currentHolding`：期末持仓用 `getStockCloseOnOrBefore` 估值，`attachBuyDayReturn` 补买入当日收益。
   - `summary`：`tradeCount / winCount / winRate / ...calcDrawdownStats / overallReturn（逐笔复利+期末浮盈） / holding`。
   - `seenStocks`：回测期间买入过的股票。
   - `buyChecks` 建议包含：板块选择（10 日占比窗口、差值）、成分股过滤、N 日涨幅前 5 明细、9:40 未涨停、分时涨幅>0、现价>开盘价、仓位与时段。

8. **为减少重复网络与磁盘**
   - 不新增自有磁盘缓存；只依赖现有 `自选股全量股票过去分时数据` 与 bars 缓存。
   - 每日 `clearTlineCache()`；按日命中板块只加载该板块成分股。
   - bars 只对「当日命中板块」预拉，且 `ensureBarsForCodes` 全局复用。
