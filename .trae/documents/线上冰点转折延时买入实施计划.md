# 线上冰点转折 15 分钟延时买入 · 实施计划

## Context

回测侧「快进快出」系列已经实现：连续两日冰点（上一交易日 `hasIce: true` + 当日分时科技情绪 ≤ `TECH_ICE_THRESHOLD(-39)`）时，买点触发后延时 15 分钟，按「板块区间涨幅差值」挑选资金聚焦的主线板块，再从板块与科技自选股的交集中选股，板块内均选不出时回退全量自选股。

现在要把同一套规则同步到线上「科技进攻」与「攻防兼备」两种模式：

- 买点触发瞬间，全局买点卡片改为提示「冰点转折，延时 15min 观察资金聚焦主线板块」，不立即给出个股；
- 后端开始 15min 计时，到点后通过 WebSocket 推送具体买入个股；
- 延时到点不受 13:30 买入时段限制（13:20 触发 → 13:35 仍可买入）；若到点落在午休（11:30–13:00），顺延到 13:00 执行；
- 飞书在「触发」和「到点」两个时点都发；
- 全局 debug 抽屉新增「冰点转折延时触发」按钮，点击后弹出 MOCK 等待卡片。

前端「全局买点卡片」实际实现位于 `GlobalDiagnosisAlert` 组件（在 `App.jsx` 中挂载），因此改动落在该组件，`App.jsx` 本身只需确认挂载关系，不改逻辑。

## 一、后端

### 1. 新建 `server/src/service/iceDelayBuy.js`

状态机（10s tick 驱动，非 setTimeout，便于重启恢复）：

- 常量：`DELAY_MIN = 15`、`LOOKBACK_MIN = 20`（起点 = 触发 − 5min，终点 = 触发 + 15min）、`BLOCK_TAGS = ['中性','进攻']`、状态文件 `server/src/data/ice_delay_buy_state.json`。
- `isIceTransition()`：
  - 上一交易日（`getPrevTradingDay`，见 `server/src/utils/tradingDay.js`）在 `getAllTechIndexData()` 中 `hasIce === true`；
  - 当日 `getTechEmotionIntraday().data[YYYYMMDD]` 任一 `value <= TECH_ICE_THRESHOLD`（从 `buySellBacktest/constants.js` 复用常量）。
- `captureStartMap()`：从 `getBlockHistory()`（`block_data_change_time.json`，`time` 为 `HH:mm`）取 `time <= 当前-5min` 的最后一条，生成 `{blockName: avgChange}`；无历史时回退 `getBlockData()`。
- `canTrigger(bucket)`：无 pending、非当日已完成、且该桶未触发过。
- `trigger({ mode, bucket })`：
  - 写入 pending `{ date, mode, source:'tech', triggerTime, triggerBucket, executeAtTs, startMap }` 并落盘；
  - `wsServer.broadcast({ type:'ice_delay_wait', mode, bucket, ts, open:true, data:{ phase:'wait', source:'tech', delayMin:15, triggerTime, executeTime, message } })`；
  - `sendFeishuText('⏳【冰点转折·延时观察】…')`；
  - 返回 true，供调用方抑制普通科技买点通知。
- `computeExecuteAt(triggerAt)`：`triggerAt + 15min`；若落在 11:30–13:00，取当日 13:00。
- `tick({ mode, data })`：pending 且 `Date.now() >= executeAtTs` → 清 pending 落盘 → `resolveDelayedPick()` → 广播 `buy_point`（`open:true`）→ 飞书。
- `resolveDelayedPick()`：
  - `getBlockData()` 取 `tag ∈ {中性, 进攻}` 的板块，`delta = avgChange - startMap[blockName]`，降序；
  - `getTopGainersByMarket(null, 1000)` 拿全部科技自选股行（`markets.cybMain + markets.star`），过滤 `matchesBuyPoint === true && prevOneWord !== true && isLimitUp !== true`；
  - 逐板块取「板块成分股 ∩ 上述可买池」，按 `change3d` 降序取第一只；第一个有结果的板块即选中；
  - 全部板块失败 → 从全量可买池按 `change3d` 取第一只，标记 `fallback: true`；
  - 返回 `{ stock, board, fallback, delta, reason }`。
- 到点广播的数据：触发时最近一次诊断 `data`（由 `buyPointPushService` 传入）+ `iceDelay: { phase:'ready', triggerTime, executeTime, delayMin, board, fallback, reason }` + `buyable:[stock]`；`mode==='attack_defense'` 时令 `data.tech.allPassed = true`，同时把顶层 `allPassed/reverse.allPassed` 置 false，使卡片只展示科技腿；无标的时 `buyable: []` 并只发飞书文本说明。
- 到点飞书：有标的 `notifyBuyPointFeishu({ mode, source:'tech', buyStocks:[...] })`；无标的 `sendFeishuText`。
- 导出 `{ isIceTransition, canTrigger, trigger, tick, hasPending, computeExecuteAt }`。

### 2. 修改 `server/src/service/buyPointPushService.js`

- `require('./iceDelayBuy')`。
- `tick()` 在 `runDiagnosis` 与 `open:false` 广播之后，先 `await iceDelayBuy.tick({ mode, data })` 处理到点买入。
- 单模式（科技进攻）命中分支：`canonicalHit` 且新桶时，先判断 `iceDelayBuy.canTrigger(bucket) && iceDelayBuy.isIceTransition()`；成立则 `await iceDelayBuy.trigger(...)`、写状态、`return`（不发普通飞书、不发普通 `open:true`）。
- `tickAttackDefense(mode, data, bucket)`：`techHit` 且新桶时同样先判断冰点转折；命中则触发等待、写 `lastNotifiedBuckets.tech`，并**跳过** tech 的飞书与 `open:true` 广播；情绪游资（ew）源的通知保持原样。
- 等待期内普通 `open:false` 诊断广播保留（前端卡片实时刷新）。
- 注意：延时到期广播发生在 `tick` 内，已被 `isInPushWindow`（9:30–15:00、午休跳过）保护，13:30 之后仍可执行。

## 二、飞书

- 触发时：`feishuNotify.sendFeishuText`，内容包含触发时间、计划买入时间、提示语。
- 到点有标的：`notifyBuyPointFeishu({ mode, source:'tech', buyStocks })`（科技卡片，含建议仓位）。
- 到点无标的：`sendFeishuText` 说明「15min 观察结束，当前无满足条件的可买标的」。
