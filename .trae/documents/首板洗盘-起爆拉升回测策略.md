# 新增回测策略：首板洗盘-起爆拉升

## Context（背景与目标）

回测页（`盯盘工具/src/pages/backtest/index.jsx` 内嵌 `BacktestDrawer`）的策略下拉里目前没有「首板洗盘-起爆拉升」。用户要求新增该策略，**仅作用于回测**，线上实盘不做任何改动：

- **选股**：回测日 D 回溯过去 **15 个交易日**（严格不含 D），候选来自**两条并列路径**：
  - **路径 A（首/二板洗盘）**：出现过**首板或二板**的股票；若 15 日内出现过 **≥3 板**，或**任意连续 3 个交易日滑动窗口的最大涨幅 > 20%**，则剔除。**首板/二板的出现时间距买点日 D 须至少相隔 3 个交易日**（近 2 个交易日内才涨停的不算）。
  - **路径 B（三日放量起爆）**：15 日内存在某个**连续 3 个交易日窗口**，其**区间最大涨幅 > 10% 且 < 25%**，并且**该窗口内成交量最大的那一天，成交量 ≥ 窗口前一个交易日成交量的 2 倍**。满足即纳入候选（不要求有涨停、不受路径 A 的「距今 ≥3 交易日」限制）。
  - 两条路径合并去重；**≥3 板**对两条路径都是硬性剔除条件。
- **买点**（两条，先到先得）：① **竞价涨幅 > 5%** → 直接在竞价 **9:30** 买入；② 当日盘中**分时涨幅首次达到 +9%** 时买入。
- **卖点**：与「情绪游资-极致胜率」**顺周期腿一致**，但**去掉「盘中 1 分钟内跳水 ≤ -3%」这一条**。
- **仓位**：每次出手**半仓**（权重 0.5，单持仓）。

实现方式：仿照 [`emotionBurstDriftBacktest.js`](file:///Users/xieyin/Desktop/盯盘工具/server/src/service/buySellBacktest/engine/emotionBurstDriftBacktest.js)（同样是「+9% 买点 + 半仓单持仓 + 复用极致胜率卖点」）新增一个独立回测引擎，通过 `firstBoardWashMode: true` 标记注册与分发。

## 已确认的关键口径与决策

| 项 | 决策 | 依据 |
| --- | --- | --- |
| 15 日首/二板池 | `getRecentMultiLianbanOccurrences(dateStr, 15, 1)`（逐日记录，`minBoardCount=1` 含首板），按 code 汇总：任一日 `lianbanCount >= 3` → 剔除；否则最大连板数 ∈ {1, 2} | 需拿到「每一次首/二板的出现日期」以满足「至少隔 3 个交易日」约束 |
| 首/二板距今间隔 | 取该股窗口内**最近一次**首/二板日期 T，要求 **`windowLen - indexOf(T) >= 3`**（即 T 距 D 至少 3 个交易日；近 2 个交易日内才涨停的剔除） | 用户新增约束，体现「先洗盘、后起爆」 |
| 三日滑动窗口最大涨幅（路径 A 过滤） | `maxSlidingWindowRangePct(code, past15Dates, 3) <= 20`，口径 = (最高收盘价 − 最低收盘价) ÷ 最低收盘价，与仓库既有「区间最大涨幅」一致 | [extremeWinPool.js](file:///Users/xieyin/Desktop/盯盘工具/server/src/service/buySellBacktest/engine/extremeWinPool.js#L84-L99) |
| 路径 B 放量起爆 | 枚举 15 日内全部连续 3 日窗口，用 `stockWindowRangePct(code, 窗口3日)` 求区间最大涨幅，要求 **> 10 且 < 25**；窗口内 3 日成交量取最大者，与**窗口前一日成交量**比较，要求 **`maxV >= 2 * vBase`**。命中即纳入候选 | 用户新增纳入条件；涨幅与路径 A 同一口径 |
| 成交量取数 | 新增 `stockVolumeAt(code, dateStr)`（读 `barsCache` 返回当日 `v`，缺失返回 null）到 [keyBlockData.js](file:///Users/xieyin/Desktop/盯盘工具/server/src/service/keyBlockData.js#L607-L630) 并加入导出，同时在 [deps.js](file:///Users/xieyin/Desktop/盯盘工具/server/src/service/buySellBacktest/deps.js#L6) 的 import/export 中透传 | 现有导出只有成交量比值（`stockVolumeRatioAt`）与均值（`stockPriorAvgVolume`），没有原始成交量 |
| 路径 B 基准日 | 为保证每个 3 日窗口都有「前一日」，窗口扫描使用 **16 个交易日**（`getPastTradingDates(dateStr, 16)`），只在后 15 日开窗，基准日 = 窗口起点的前一日 | 否则 15 日窗口首日开窗时没有前一日成交量 |
| 日K缺失（返回 null） | **保守剔除**（无法确认未超过 20% / 无法确认量能条件） | 与极致胜率候选池「数据不足不入选」一致 |
| 是否限主板 / 题材黑名单 | **不额外限制**（用户未要求）；仅剔除全局 `EXCLUDED_CODES` | 与 drift 策略「只买主板」不同 |
| 竞价买点 | 9:30 首条分时点（竞价/开盘价）涨幅 **> +5%** → 9:30 直接买入；若同时 ≥ 涨停阈值（`limitUpThresholdOf(code)`）视为一字板买不进，跳过该股 | 用户新增；优先级高于 +9% 盘中买点 |
| 盘中买点时段 | 9:30–14:30（`BUY_START_MINUTE=930`、`BUY_CUTOFF_MINUTE=1430`），分时涨幅首次 ≥ +9% 买入 | 与 drift / 极致胜率买入截止一致 |
| 涨停买不进阈值 | `limitUpThresholdOf(code)`（主板 9.5、创业板/科创板 19），不再固定 9.5 | [extremeWinScores.js](file:///Users/xieyin/Desktop/盯盘工具/server/src/service/buySellBacktest/engine/extremeWinScores.js#L36) |
| 卖点 | `scanLeaderPriceSell({ costLinePct: -5, costLineSustainMinutes: 0, enableOpenGapReboundSell: true, disableMinutePlummet: true })` + 持仓第 **3** 个交易日尾盘 14:57 收益未达 +10% + 尾盘收盘抗分歧 < 6 | 极致胜率顺周期腿，**去掉⑩单分钟跳水**（用户要求） |
| 时间桶 | 沿用 campData 的 5min `timeBuckets`（与 drift 一致），价格类卖点内部按 1 分钟回溯 | 用户未指定粒度 |

> 备注：按用户字面规则，二板股因两连板累计涨幅通常已超 20%，会被「三日窗口 > 20%」过滤掉大部分，实际候选以首板为主。这是规则本身的结果，不做额外放水。

## 改动清单

### 1. 新建独立引擎（后端）

**新文件** `server/src/service/buySellBacktest/engine/firstBoardWashBacktest.js`，导出 `runFirstBoardWashBacktest(startDate, endDate, strategyId, onProgress)`。

结构与 `emotionBurstDriftBacktest.js` 对齐：

- 依赖：`batchParallel / ensureBarsForCodes / getPastTradingDates / getRecentMultiLianbanOccurrences / getSingleStockTlineDataByDate / getStockCloseOnOrBefore / getTrainingCampDates / loadTrainingCampData / getMonitorStocks / stockWindowRangePct / stockVolumeAt`（`../deps`）、`maxSlidingWindowRangePct`（`./extremeWinPool`）、`limitUpThresholdOf / round2 / loadTlinePoints / clearTlineCache`（`./extremeWinScores`）、`scanLeaderPriceSell`（`./leaderSellMinute`）、`EXCLUDED_CODES`（`../constants`）、`attachBuyDayReturn / calcDrawdownStats`（`../utils/tradeStats`）、`TWO_BUY_LEG_WEIGHT / computeTwoBuyAccountReturn`（`./twoBuy`）、`calculateReplayResilience`（`../diagnose/sellPoint`）。
- 常量：`LOOKBACK_DAYS=15`、`SLIDE_DAYS=3`、`MAX_SLIDE_RANGE_PCT=20`、`MAX_ALLOWED_BOARD=2`、`BOARD_GAP_MIN_DAYS=3`、`BURST_MIN_RANGE_PCT=10`、`BURST_MAX_RANGE_PCT=25`、`BURST_VOLUME_MULTIPLE=2`、`OPEN_AUCTION_BUY_PCT=5`、`BUY_TRIGGER_PCT=9`、`BUY_START_MINUTE=930`、`BUY_CUTOFF_MINUTE=1430`、`TAIL_MINUTE=1457`、`WEAK_TRADE_HOLD_DAYS=3`、`WEAK_TRADE_MIN_GAIN_PCT=10`、`RESILIENCE_SELL_MAX=6`、`LEADER_RESILIENCE_INDEX_CODE='sh000001'`。
- 主循环逐日：
  1. `loadTrainingCampData(dateStr, { allowMissingFund: true })`，失败/无桶则记入 `skippedDates` 继续。
  2. 惰性 `ensureSelected()`：
     - `scanDates = await getPastTradingDates(dateStr, 16)`（升序，含基准日）；`boardDates15 = scanDates.slice(1)`。
     - `getRecentMultiLianbanOccurrences(dateStr, 15, 1)` 得到逐日连板记录，按 code 汇总（同 code 同日去重）：任一日 `lianbanCount >= 3` → 记入 `bannedCodes`。
     - **路径 A**：对不在 `bannedCodes` 的股票，`latestDate` = 最近一次首/二板日期，要求 `15 - indexOf(latestDate, boardDates15) >= 3`；再要求 `maxSlidingWindowRangePct(code, boardDates15, 3) <= 20`（null 剔除）。
     - **路径 B**：对不在 `bannedCodes` 的股票（含「15 日内无首/二板」者），遍历窗口起点 `s = 1..scanDates.length-3`，取 3 日窗口 `[s, s+1, s+2]` 与基准日 `scanDates[s-1]`：
       - `range = stockWindowRangePct(code, 窗口3日)`，须 `> 10 且 < 25`；
       - `v0/v1/v2 = stockVolumeAt(code, 各日)`，`vBase = stockVolumeAt(code, 基准日)`，须全部有效且 `max(v0,v1,v2) >= 2 * vBase`；
       - 命中即纳入候选（记录该窗口信息用于 `buyChecks`）。
     - `ensureBarsForCodes` 需覆盖参与扫描的全部股票；**路径 B 的扫描范围 = 全部自选股（`getMonitorStocks()`）∪ 15 日内出现过涨停的股票**（不做全市场逐股日K预拉）。
     - 合并两路径 → 去重 → 剔除 `EXCLUDED_CODES` → `candidates`。
  3. 惰性 `ensurePool()`：`batchParallel(candidates, …, 8)` 加载每股当日 `loadTlinePoints`。
  4. `computeEntry()`：
     - **竞价买点**：取首条分时点 `p0`（9:30 竞价/开盘价），`openChg = (p0.lastPx - preclose)/preclose * 100`；若 `openChg > 5` 且 `openChg < limitUpThresholdOf(code)` → 记 `auctionHit = { minute: p0.minute, px, chg }`（9:30 买入）；若 `openChg >= 涨停阈值` → 记入「一字板买不进」。
     - **盘中买点**：在 9:30–14:30 找**首个** `chg >= 9` 且 `< 涨停阈值` 的分钟，记 `hitMemo`；达到涨停阈值后若后续炸板回落到 9%~阈值之间仍可买。
  5. 每桶先处理**隔夜持仓卖点**（`dateStr > position.buyDate`）：分钟级价格卖点（`disableMinutePlummet: true`，即不含⑩单分钟跳水）→ 第 3 日尾盘 +10% → 尾盘抗分歧 < 6；成交后 `position=null`、`soldThisDate=true`。
  6. 再处理**买入**（`!position && !soldThisDate && bucketMinute <= BUY_CUTOFF_MINUTE + 5`）：优先取竞价命中（9:30 桶即成交，多只候选取竞价涨幅最大者）；否则取 `hit.minute <= bucketMinute` 中最早者（同分钟涨幅更大者），按该分钟分时价买入，`weight=0.5`，记录 `buyReason` / `buyChecks`（选股池、首/二板距今间隔、3 日窗口涨幅、触发方式（竞价/盘中）、被顺延的涨停候选）。
- 结果组装与 drift 一致：`trades`（`returnRate = rawReturnRate * 0.5`）、期末 `currentHolding`、`computeTwoBuyAccountReturn` 得 `overallReturn`、`attachBuyDayReturn`、`summary`、`seenStocks`。

## 验证方式

1. 语法校验：对改动的后端 JS 逐一 `node --check`；前端改动由页面加载验证。
2. 后端单策略回测（服务运行后）：
   `POST http://127.0.0.1:3000/training_camp/backtest`，body `{ strategy: 'first_board_wash_relaunch', start: '20260901', end: '20261030' }`（或前端点「回测」）。
3. 断言检查：
   - 所有 `trades[].buyTime` 落在 9:30–14:30；`weight=0.5`；
   - 竞价买入样本：`buyTime === '09:30'` 且 `buyChange > 5`；
   - `buyChecks` 中「首/二板距今 ≥ 3 交易日」「三日窗口最大涨幅 ≤ 20%」项均通过；路径 B 入选项的「三日窗口涨幅 10%~25% + 量能 ≥2 倍」项通过；
   - 全部 `sellReason` **不含**「1 分钟内跳水」，且出现「持仓第 3 个交易日尾盘…」或价格类卖点。
4. 前端：打开回测页 → 策略下拉出现「首板洗盘-起爆拉升」→ 运行后在「策略说明」弹窗看到四段式规则、买卖规则列表与极致胜率口径一致。
5. 回归：随机跑一次 `emotion_burst_drift_leader` 与 `hot_money_extreme_win`，确认新增分发分支未影响既有策略（`regularIds` 过滤仅新增一个排除条件）。
