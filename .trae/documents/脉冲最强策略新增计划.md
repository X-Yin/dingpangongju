# 新增「脉冲最强-{n}日涨幅最大-快进快出」策略（n = 2 / 3 / 4）

## Context

现有「{n}日涨幅最大&三日情绪-30快进快出」系列中，只有在「连续两日冰点」门禁成立时（上一交易日 `hasIce: true` 且当日任一分时科技情绪 ≤ `TECH_ICE_THRESHOLD = -39`），买点触发后才走「板块发酵延时」选股：
触发后等 15 分钟（`EMO_QUICK_RAISED_BLOCK_DELAY_MIN`），看目标时点往前回溯 20 分钟（`EMO_QUICK_RAISED_BLOCK_LOOKBACK_MIN`）内「中性/进攻」板块的区间涨幅差值，按差值降序逐个板块，在「板块成分股 ∩ 全量自选科技股 ∩ 当桶有行情」的交集里选 n 日涨幅最大的科技股。

用户要求新增一个独立策略「脉冲最强-{n}日涨幅最大-快进快出」，把它变成**每次买点触发都无条件执行**的选股逻辑（去掉冰点前置条件），n 取 2/3/4，即 3 个策略；其余买点诊断、快进快出卖点、半仓、资金净流入动态阈值等全部沿用现有快进快出系列。

## 方案

不新增引擎分支，完全复用现有 `pendingRaisedBuy` 延时建仓机制，只把「冰点门禁」替换为「策略标记 `pulseBlockPick: true` 无条件成立」。

### 1. 后端策略注册

**`server/src/service/buySellBacktest/strategies/descs.js`**
- 新增 `PULSE_DESC(n)`：在 `EMO_QUICK_DESC(n)` 文案基础上，追加「脉冲最强选股」段落——每次买点触发后不立刻买入，等 15 分钟到目标桶，按目标时点回溯 20 分钟的「中性/进攻」板块区间涨幅差值降序，逐个板块在其与全量自选科技股的交集内选 n 日涨幅最大者；全部板块选不出则回退全量自选股；目标时点落在午休或 13:30 之后则本次不买。
- 加入 `module.exports`。

**`server/src/service/buySellBacktest/strategies/families/emoQuick.js`**
- 新增 3 条（放在现有快进快出条目之后）：
  - `highest_2d_gain_emoquick_pulse`，name「脉冲最强-2日涨幅最大-快进快出」
  - `highest_3d_gain_emoquick_pulse`
  - `highest_4d_gain_emoquick_pulse`
- 字段：`{ id, name, desc: PULSE_DESC(n), emoQuickOut: true, pulseBlockPick: true }`
- id 保留 `highest_{N}d_gain` 前缀与 `_gain` 片段，使 `pickBest.js`（N 日窗口 / 涨幅模式 / 涨幅并列抗分歧 / 过热门槛）与 `registry.js` 的自动 desc 追加逻辑全部照常生效。
- 注意 `selectors/delegates.js` 的正则 `^highest_(\d+d\d*)_gain_emoquick$` 不匹配带 `_pulse` 后缀的 id，因此需在引擎里显式补挂 `emoQuickOut`（见第 2 步）。

### 2. 回测引擎：冰点门禁 → 无条件触发

**`server/src/service/buySellBacktest/engine/rangeBacktest.js`**
- 在策略配置解析处（`emoQuickHalfBuy` 附近）新增 `const isPulseBlockPick = strategy.pulseBlockPick === true;`
- 首次建仓判断（约 326 行）：
  `const iceGateOpen = emoQuickHalfBuy && (isPulseBlockPick || isTechIceGateOpen(prevDateStr, timeBuckets, bi));`
- 延时执行处（约 476 行）同样传入 `emoQuickHalfBuy && (isPulseBlockPick || isTechIceGateOpen(...))`
- `openFirstPosition` 内 `picked.emoQuickOut` 挂载条件（约 209 行）追加 `|| strategy.pulseBlockPick === true`，否则该策略不会计算快进快出标注、次日 10:00 强卖与 -2% 止损失效。

**`server/src/service/buySellBacktest/engine/rangeBacktestMulti.js`**
- 与单策略版完全同构的三处改动：`isPulseBlockPick` 常量、329 行建仓门禁、478~481 行延时执行门禁、218 行 `picked.emoQuickOut` 条件。

### 3. 常量与缓存版本

**`server/src/service/buySellBacktest/constants.js`**
- 把 3 个新 id 加入 `OPENING_BELOW_RATIO_STRATEGY_IDS`（检查4「开盘后自选科技股低于开盘价」按比例收紧，与快进快出系列同口径），并更新注释中的策略数量。

**`server/src/service/buySellBacktest/paths.js`**
- 在 `CACHE_VERSION_BY_STRATEGY` 中登记 3 个新 id 为 1（新策略无旧缓存，显式登记便于后续改规则时递增）。

### 4. 前端回测页

**`盯盘工具/src/pages/trainingCamp/components/BacktestDrawer/index.jsx`**
- `STRATEGY_OPTIONS` 新增 3 项（value 为上述 id，label 与策略 name 一致）。
- `STRATEGY_CATEGORIES` 的 `emo_quick`（快进快出系列）ids 数组加入 3 个新 id。
- `STRATEGY_SPECIFIC_NOTES` 新增 3 个 key，`group: '快进快出系列'`，bullets 参照 `highest_3d_gain_emoquick` 的写法，并追加「脉冲最强」板块选股 / 15 分钟延时 / 20 分钟回溯 / 回退全量自选股的说明条目。

### 5. 无需改动（已确认自动生效）

- `strategies/registry.js`：周期过滤、半仓、涨幅对比顺延、过热门槛、涨幅并列抗分歧等 desc 按 id/字段自动追加。
- `engine/pickBest.js`：`/(\d+)d/` 解析 N、`includes('_gain')` 判定涨幅模式、并列按抗分歧排序均为自动。
- `engine/quickRaisedBlock.js`：板块排序、回溯、延时目标判定全部直接复用。
- `engine/indexGate.js`：跨指数双门禁按 `Object.keys(STRATEGIES)` 自动纳入。
- `script/backtest-worker.js`：按 `Object.keys(STRATEGIES)` 自动全量回测与汇总。

## 验证

1. 语法/加载：`node -e "require('./server/src/service/buySellBacktest')"` 确认注册成功、`STRATEGIES` 含 3 个新 id。
2. 单策略回测：
   `node script/backtest-worker.js --strategies highest_2d_gain_emoquick_pulse,highest_3d_gain_emoquick_pulse,highest_4d_gain_emoquick_pulse --prebuild --start 20260701 --end 20261023`
   - 确认无异常、每个策略有交易记录。
   - 抽查买入明细：应普遍带 `raised_block_delay`（触发 → +15min 成交时点），多数带 `raised_block_pick`（板块名 / 区间涨幅差值 / 排名），少数带 `raised_block_fallback`（全部板块选不出时回退全量自选股）。
   - 确认 `emo_quick_out` 标注存在，次日 10:00 强卖与 -2% 止损生效。
3. 前端：刷新回测页，策略下拉「快进快出系列」中出现 3 个新策略，规则说明弹窗文案正确，能正常发起回测并展示结果。
