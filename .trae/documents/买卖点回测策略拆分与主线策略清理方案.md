# 买卖点回测：拆分单文件巨兽 + 删除「情绪游资-主线炒作」策略

## Context（背景与目标）

`server/src/service/buySellBacktest.js` 已达 **5858 行 / 394KB**，维护成本高。经核实，它并非"每个策略一段独立代码"，而是：

- **2 个共享引擎**：`runRangeBacktestInner`（range 引擎）与 `runKeyBlockBacktest`（keyBlock 引擎）
- **1 张策略注册表** `STRATEGIES`：所有策略靠字段开关区分（`keyBlockDays / iceMode / iceReverse / iceIntradayGain / iceMainline / tailDip / emoAvgBuy / nextDayOpenSell / emoQuickOut / twoBuy / diffBlock / halfDayAfternoon / costLinePct` 等）
- 策略专有逻辑散落在 `pickBestStock` 与两个引擎的 `if (strategy.xxx)` 分支里

同时要删除一个已废弃策略 **「情绪游资-主线炒作」**（id `hot_money_mainline`，标志 `iceMainline: true`）的全部前后端代码。

**用户已确认的两项决策：**
1. 拆分粒度：**激进** —— 除功能模块拆分外，把策略行为也 hook 化（把 `pickBestStock` / 引擎卖点里按策略分派的分支抽成「策略 selector / sell hook 注册表」），真正做到策略行为尽量独立成文件。
2. 顺带清理：`buySellBacktest.js.bak3.js` 旧备份、两份主线设计文档、临时脚本 `mainline-sectors.js` 及其 HTML；主线回测缓存 `backtest_hot_money_mainline_*.json` 一并删除。

**预期结果**：单文件拆成 `buySellBacktest/` 目录下的多层模块；策略元数据按家族独立成文件、策略行为按 selector/sell-hook 独立成文件；公共函数集中于 `utils/`。外部 `require('./service/buySellBacktest')` 路径与 25 个导出符号契约保持不变；除被删策略外，所有策略回测输出**逐字节等价**。

## Phase C：策略行为 hook 化（激进）——已部分落地

在功能模块基础上，把"按策略分派"的分支改为注册表 / 独立 hook 驱动。**已落地（每步以 `/tmp/bt_c0` 逐字节 diff，均 IDENTICAL）**：

1. **range 引擎卖点 sell-hook** → 新增 `engine/sellHooks/`：
   - `nextDayOpen.js`（三日情绪均值策略次日开盘卖点）
   - `emoQuickOut.js`（情绪快进快出：10:00 强卖 + 盘中跌破成本线止损 + 强卖豁免；返回强卖日期）
   - `generalSell.js`（通用 7 条件卖点诊断）
   `engine/rangeBacktest.js` 与 `engine/rangeBacktestMulti.js` 均只保留调度（`if (strategy.xxx) hook(...)`），不再内联策略卖点细节；multi 传 `st.positions / strategy / singleTrades`，与 single 复用同一 hook。
2. **选股委派注册表** `engine/selectors/delegates.js`：把 `pickBestStock` 内「按策略 id 路由到其它策略 / 独立选股函数」的 5 个分支（抗分歧弱转强 / 情绪开关 / 情绪快进快出 / 研报双门 / 科技板块前三）集中到一处；`pickBestStock` 注入自身避免循环 require，保留共享流水线（候选过滤 / 涨停与一字板顺延 / 抗分歧门槛 / 周期过滤 / 排序），`resolveDelegatePick` 未命中返回 `undefined` 交回主流水线。

**布局说明（相对原计划的调整）**：selectors 与 sellHooks 依赖 engine / diagnose 层模块，若置于 `strategies/` 会反转「engine → strategies 单向依赖」的方向。因此改为 `engine/selectors/` 与 `engine/sellHooks/`，保持严格单向依赖。

**暂缓（评估后判定为"纠缠型"逻辑：拆分收益低、回归风险高）**：
- `runKeyBlockBacktest` 内 ice/iceReverse 卖点：与斜率状态机、持仓权重、逐桶竞价低开自救窗口深度耦合（约 `keyBlockBacktest.js` 500–650 行），无法在不改写状态机的前提下干净抽出。
- `pickBestStock` 内「指标计算 + 排序」细粒度 selector：当前是「共享流水线 + 参数化开关」（`lowMode / tiebreak / 窗口类型`），再拆成每策略一个 selector 文件只增加间接层，不提升可读性。

**验证 C**：
- `diff -rq /tmp/bt_c0 /tmp/bt_c1`（sell-hook）与 `/tmp/bt_c0 /tmp/bt_c2`（delegate）均 **IDENTICAL**（21 个策略）。
- 符号契约 24 项齐全；`STRATEGIES` 71 个、desc 改写顺序正确（`highest_gain` 含「≥ 11」/`highest_3d_gain` 含「顺周期过滤」/`tail_dip_emo3_3d_gain` 含「买入环境门禁」）；`hot_money_mainline` 已移除。
- 消费方冒烟：`backtestReport.js` / `buySellDiagnose.js` / `backtest-worker.js` / `randomSimWorker.js` 均加载通过；worker 全 71 策略跑通并重建回测缓存。
